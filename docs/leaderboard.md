# 调查员统计与排行榜

登录后从导航“排行榜”进入，也支持 `/#/leaderboard`。面板统计所有注册用户，包括尚未开局的账号；摘要展示注册人数、已开始调查人数、完成调查总局数和结局收集总数。结局收集总数按用户累加，同一结局被两名用户收集计两次。

主榜默认按结局收集数降序，可切换通关剧本数、完成局数和累计成就点数。主指标同分并列，采用1、1、3的名次；同分用户按用户名固定顺序展示，翻页不会改变其名次。每页20人，自己的总榜名次单独显示，即使自己不在当前页。支持刷新、异常重试和桌面／手机布局。

## 统计口径

- 结局收集数：已确认且可收藏的结局，按剧本ID＋结局ID跨内容版本去重；保留可验证的旧版本历史。
- 通关剧本数：至少获得一个上述结局的剧本数量，包括死亡或疯狂结局。
- 完成局数：抵达上述结局的不同游戏局数量；重复游玩同一结局可增加完成局数，一局的重复历史帧不重复计数。
- 开始局数：该账号保存的游戏局总数，包括未完成的局。
- 累计成就点数：已收集结局对应奖励的总和，包含未领取奖励；已经领取的奖励沿用领取时记录的金额。消费不降低累计值。

通关与成就共用 `confirmed-endings.ts` 的来源版本校验与历史过滤。待确认骰点、被重掷取代的结果、`collect: false` 的退场和无法核验内容版本的历史不计通关，不依据客户端传入的分数或当前状态推测。查询不领取奖励、不改变余额或存档。没有新增数据库表和迁移。

## 接口与数据范围

`GET /api/leaderboard?sort=endings&page=1&limit=20` 需要登录，排序可选 `endings`、`stories`、`runs`、`points`；每页1–50人，超出末页会返回实际末页。返回摘要、当前页、总页数及当前用户自己的统计。响应只含用户名、名次、游戏统计及当前用户标记，不返回账号ID、密码、会话、存档ID、剧情正文或具体结局名称。

服务端一次汇总账号、奖励记录及已确认结局历史，避免逐个用户重复扫描全库历史；全局排序后再分页，名次不在客户端计算。

## 验证

`tests/leaderboard.test.ts` 使用独立数据库检验全部24个账号、未开局账号、同分与分页、不同排序、旧版本与旧格式历史、同结局和重复历史去重、待确认／重掷取代／退场过滤、消费后累计点数、身份验证、返回字段、重启与只读性；另通过真实认证开局及行动确认新结局立即进入统计。

`tests/browser/leaderboard.spec.ts` 验证桌面／手机的导航、登录、服务异常重试、分页、自身名次、排序、真实通关后的刷新、页面重载和横向溢出。截图保存到 `docs/screenshots/leaderboard-*.png`。

本轮验收：全项目774项测试、类型检查及生产构建通过；排行榜桌面／手机浏览器测试2/2通过，验证导航、异常重试、分页排序、实际通关刷新、重载和无横向溢出，并目视检查两种尺寸的截图。
