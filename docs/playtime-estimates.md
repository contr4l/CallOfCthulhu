## 统计口径

统计加载后的最新正式发布包，按游戏引擎的 `project`／`advance` 从入口重放实际合法行动和保存的骰点，而不是把图上的连线当作可达路线。静躁、潮汐见证须与发布 `story.json` 的 SHA-256 匹配；每一步核对原节点、目标节点及骰子范围，最后必须结束。

采用玩家可见的中文正文，去除纸面编号／操作提示；汉字数不含标点，混入的英文另按单词计。全部正文按相同正文块去重，避免辅助节点重复计数。单局计数跳过相邻场景重复正文，例如同一段落等待检定或填写角色卡；离开后再次返回同一段落仍计阅读时间。标题、帮助文字、选项标签不计入正文量，它们的阅读和操作由交互预算近似覆盖。

计算模型的速度是公开的规划假设，没有引用或声称测得某种人群平均值：

- 中文每分钟300–500汉字；正文中英文每分钟150–220词。
- 普通推进每步2–4秒；需要选择时额外8–20秒。
- 出现检定或规则骰结果时额外8–18秒。
- 每次属性／技能分配2–5分钟；初始建卡入口与角色选择2–5分钟。

逐条路线分别计算快读／慢读两个预算，目录展示取样本最低快读预算与最高慢读预算，按5分钟取整，并标注“约”。目前模型为33.4–76.3、20.4–90.7、13.9–159.6分钟，不能把小数解释为真实完成时间的精度。

英文正文、低速打字机动画、长时间思考、查阅规则、反复回读和暂停可能使实际时长超出展示范围；熟练复玩或更早失败可能短于下限。没有使用低覆盖度的样本来承诺玩家在指定时间内完成。以后可以使用经同意收集的实际活跃游玩时间校准模型，暂停和离线时间应单独扣除。

## 复算与展示

```sh
npm run story:playtime
npm run story:playtime -- --check
```

脚本 `tools/story/estimate-playtime.ts` 生成完整数值报告 `docs/playtime-estimates.json` 与目录数据 `apps/api/src/modules/playtime-estimates.json`。修改正文或见证后重新运行，并同步本说明的摘要。`--check` 会重放路线并对照已保存的结果，避免报告悄然过期。

API 只在剧本 ID 和内容版本匹配时使用估算的展示时长，未估算的版本沿用原元数据。这是目录展示修正，不修改剧本发布文件、角色、骰点或旧存档；剧本规则仍绑定原内容版本。
