## 测试发现与修复

旧实现将条目 57 返回 78 和条目 66 返回 57 的退出操作也标成一次性；原文允许 76→75→66 重返，随后可能耗尽全部操作而卡住。种子 5431 的完整路线复现了这个问题。

1.2.0 只移除这两处退出操作的 `once`，调查操作仍一次性，原跳转目的地、角色数值及其余规则不变。回归测试证明同一路线在 1.1.0 卡住、在 1.2.0 可完成。1.0.0／1.1.0 及其存档保留，不迁移、不重掷。

稀有结局 365 需要时间之铁与对应特殊检定分支；结局 334 的路线依原文 329，在已经历四种疯狂症状后再次发作进入。两者均有两种固定角色的合法逐步见证。

桌面检定弹窗的主按钮继承了悬停上移 1 像素的样式，在特定指针位置反复变动，浏览器无法稳定点击。为 `.modal .primary-button:hover` 取消位移后，6 条原失败路线均从开局重新完成；其他悬停反馈保持，剧情规则和存档不变。测试也等待正文／行动列表更新，并让长路线遵守现有 API 限流，未使用强制点击绕过问题。

## 覆盖与边界

- 剧本独立快照的 102 个单元／后端测试通过，含 28 条角色与结局的 API 路线；当前共享工作区最终复查 108 项全部通过。
- 40 个不同的桌面／手机浏览器用例通过：28 个全结局用例、8 个角色及代表性完整路线用例、4 个模组入口／建卡用例。首次运行 34 项通过、6 项因桌面弹窗按钮位置不稳定失败；修复后这 6 项完整重跑全部通过。
- 20,000 次有界随机游玩（两种角色各 10,000 次）没有无行动卡点，也没有超过每局 450 步上限的路线；稀有结局另由定向合法搜索补齐，不能声称均由随机抽样发现。
- 来源验证覆盖 372 个原书条目及 supplements；按偏移重组后的 UTF-8 字节与原 TXT 完全相同，包含 CRLF、包装和角色表。
- 类型检查、全部版本规则／资源／片段校验及生产构建通过。

浏览器测试在 `/tmp/coc-static-validation` 的固定快照执行，使用原有引擎加本次剧本／界面修复，排除同时开发中的商店功能以避免热更新干扰。快照只为验收；原工作区的同步改动完整保留。最终当前工作区的类型检查、108 项测试和构建也通过；商店的浏览器体验不属于此次剧本验收。

完整结局见证证明所有 14 个结局可达；随机游玩覆盖不等于穷举所有状态与骰点组合。手机测试采用 Chromium 390×844 触屏模拟，不等于真实 iOS／Android 设备验证。

## 复现

```sh
npm run story:validate
npm run typecheck
npm test
npm run build
npx playwright install chromium
npx playwright test tests/browser/static.endings.spec.ts tests/browser/static.full.spec.ts tests/browser/solo.spec.ts --project=desktop --project=mobile --workers=8
```

已有见证可通过上述测试重新执行。重建搜索数据时，先运行随机搜索；若未覆盖稀有结局，随后分别定向搜索，最后再次运行随机搜索保留同版本已找到的见证：

```sh
COC_ENDING_ATTEMPTS=20000 npx tsx tools/story/find_static_endings.ts
COC_TARGET_ROLE=0 npx tsx tools/story/target_static_ending.ts 365
COC_TARGET_ROLE=1 npx tsx tools/story/target_static_ending.ts 365
COC_TARGET_ROLE=0 npx tsx tools/story/target_static_ending.ts 334
COC_TARGET_ROLE=1 npx tsx tools/story/target_static_ending.ts 334
COC_ENDING_ATTEMPTS=20000 npx tsx tools/story/find_static_endings.ts
```

首次随机搜索缺结局时返回非零状态，应检查报告再执行定向搜索；规则图改变后旧见证不会自动复用，必须重新生成并重放。
