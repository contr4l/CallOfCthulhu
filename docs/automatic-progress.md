# 局内自动登记与章节推进

`coc7-solo@2` 模组将纸面规则编译为后端指令。玩家正文不显示“在表格上打勾”及“转到某编号”的操作要求，源 EPUB、原文片段和原始剧本数据继续保留这些文字。

## 自动登记

通用登记使用受控数据，禁止执行剧本文本中的代码：

```json
{
  "kind": "effects",
  "effects": [
    { "op": "register", "kind": "skill", "key": "spotHidden" },
    { "op": "register", "kind": "state", "key": "staircase", "label": "秘密阶梯" }
  ]
}
```

技能登记写入本局的 `flags.skillMark.<skill>` 和 `program.skillMarks`；事件与线索登记写入本局对应的 flag，名称保存在 `program.registrationLabels`。登记可放在章节效果、选项效果或检定的成功／失败效果中，条件由规则计算。`$last` 表示最近完成的技能检定；不存在相应技能或检定时拒绝登记。

重复登记同一项目不增加第二条记录，不重复产生“已自动登记”通知。登记仅影响当前局；不会修改调查员档案、其他局或全局角色成长。旧版本的 flag 指令与存档继续可用，读入后同样投影为统一记录。

公开 `SceneView.registrations` 包含 `key`、`kind` 和 `label`，页面在“本局记录表”中展示。兼容字段 `records` 继续提供名称列表。规则、角色值、登记状态与执行结果在同一局内事务保存；刷新与回忆读取不重新执行规则。

## 下一节

后端根据当前规则步骤和已保存的状态，先计算合法行动。阅读继续、检定、规则骰或条件筛选后仅有一个可执行选项时，返回唯一行动：

```json
{ "id": "next", "label": "下一节" }
```

点击时服务器重新核对这一步唯一的合法行动，而不是接受客户端提供的章节编号。需要检定则使用服务器骰子，按成功、失败或大失败路由到对应章节；页面展示已经保存的检定结果。条件已确定的唯一出路不要求玩家手动选择目标编号。`next` 不能用来绕过多项真实选择，也不能直接指定成功分支。

调查方向、孤注一掷、战斗中的反击或闪避等有实际决策含义的行动仍显示相应选项；建卡分配和投入点数仍使用输入表单。旧行动 ID 可用于已发出的请求和旧客户端，但同样接受原有条件校验。

命令以 `commandId` 幂等，并校验 `expectedRevision`。重复提交、数据库重启后的重试和多设备竞争，不会再次掷骰、重新改变生命值或重复登记。

## 验证

自动推进测试覆盖：技能／状态自动登记、重复登记去重、旧存档字段兼容、界面隐藏纸面规则、成功与失败分支、条件唯一出路、真实选择拒绝自动推进，以及命令重试和 SQLite 重启恢复。浏览器测试覆盖桌面与手机的“下一节”按钮和记录表展示。
