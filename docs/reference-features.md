# 从 cocgame 融入的交互

参考项目：[ZTGeng/cocgame](https://github.com/ZTGeng/ZTGeng.github.io/tree/master/cocgame)。实际审阅了 `game.html`、`script.js`、`chapter-map.js` 和 `coc-server.js`，按现有 React、Fastify、SQLite 架构重新实现交互，没有引入其 Vue 运行时或复制剧本文本。

[script.js](https://github.com/ZTGeng/ZTGeng.github.io/blob/master/cocgame/script.js) 中的 `characteristic-cell` 并列展示完整、一半、五分之一数值，`skills-table` 区分职业与兴趣技能，`character-form` 随剧情阶段开放填写，`usedChapters` 记录访问过的段落。当前参考代码的访问记录存在运行时，没有账号级数据库收藏；本项目在这个思路上扩展了跨局收集。

| 功能             | 当前实现                                                                                                                     |
| ---------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| 结局收集         | 回忆档案按剧本及版本列出抵达的结局、进度和经历次数。重复路线合并，未知结局只显示剩余数量。                                   |
| 章节收集         | 汇总真正展示过的原书条目；建卡、同一段落多次操作不会反复解锁。规则辅助节点按原书编号归并，不计入新的章节。                   |
| 重访收集         | 点击收藏读取已保存正文，可打开对应旅程回放；没有跳转当前游戏或重新检定的入口。                                               |
| 角色卡填写       | 调查员页面填写姓名、年龄、称谓、出生地、居住地、外貌、信念、重要之人、地点、物品和个人笔记。规则数值仍由模板和剧情建卡控制。 |
| 角色卡阅读与导出 | 属性与完整技能表同时展示普通、困难、极难值；可导出角色 JSON。个人资料不会修改已开始游戏里的角色副本。                        |
| 建卡体验         | 必选职业技能固定，选项避免重复技能，显示待分配点值与检定预览；未确认分配暂存于当前浏览器会话，刷新可恢复。                   |
| Flames 角色档案  | 属性、职业和兴趣分配成功后，把建卡结果保存回本局新建的档案角色，并保留个人资料。后续受伤或理智变化仍只属于该局。             |

## 存档契约

`GET /api/collections` 按登录账号从 `run_history` 汇总，返回总量与已解锁条目；没有未解锁条目的名称和正文。`GET /api/collections/entry` 只能取得该账号已经保存的历史视图。新增历史在场景中保存章节/结局身份，旧历史通过已公开标题与章节匹配，无需改写旧数据。按版本分别统计，避免内容升级后混用收集进度。

`PATCH /api/characters/:id` 只接收姓名和个人资料，并执行所有权、长度、年龄及 CSRF 校验。角色卡中的属性、技能、幸运、生命、模板身份不能通过资料接口修改。所有建卡结果与历史保存继续处于原有行动事务内，失败不留下半完成档案。

自动测试覆盖跨局去重、未解锁内容保护、账号隔离、旧历史恢复、只读回访、资料校验、局内角色隔离及完整剧情建卡保存。浏览器测试覆盖桌面与手机的收集展示、资料保存、检定表、导出和分配草稿刷新恢复。
